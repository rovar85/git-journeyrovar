Coding track · Lesson C8

Tests and measuring: your QA skills in code

By the end of this lesson you can:
  • write a small set of test scenarios with expected results
  • compute a pass rate and use assert as a regression alarm
  • explain how this becomes the evaluation harness for an agent

The idea

This is the lesson where you are already the expert. Chapter 9 said an agent needs a test set of reproducible failures with expected outcomes, a scorecard, and a regression suite. Testers do this every day. In code it is a list of cases, a loop that runs each one, and a comparison of actual to expected.

  • Each scenario is a dictionary: the conditions (service state, SQL, DNS) and the expected diagnosis.
  • The loop calls the function under test and compares its answer to the expectation: PASS or FAIL.
  • The task success rate is passes divided by total.
  • assert condition, "message" stops the program with an error if the condition is false. Put it at the end of a test run and any regression becomes impossible to miss.

Watch it run

Line by line

  • SCENARIOS is a list of three dictionaries. Each is a test case: the setup, plus "expect", the right answer.
  • diagnose(service, sql, dns) is the logic being tested. DNS failure first; then "stopped and SQL down"; otherwise it escalates to a human. (Note the third rule: it knows when to say I cannot tell. Chapter 9's "escalation rate" metric measures that.)
  • passed = passed + (1 if ok else 0) adds 1 for a pass. 1 if ok else 0 is a one-line decision.
  • {rate:.0%} inside an f-string formats a fraction as a percentage.
  • assert rate == 1.0, ... would crash the run with your message if any case failed. In a real project this runs every time you change anything.
From three cases to fifty

Your notes say to measure a diagnostic agent against 50 or more known failure scenarios, kept as a regression suite. This is the same program with more rows in SCENARIOS. The rows can come from your existing QA lab: every known failure mode you have reproduced becomes a case. Every time you improve the agent, you rerun the suite. If something that used to pass now fails, that is a regression.

Capability versus reliability

A rule-based diagnose gives the same answer every time, so a single run is enough. A language-model brain does not: run each scenario several times and report how often it succeeds every time (reliability, pass^k) as well as at least once (capability, pass@k). See reliability_demo.py in Chapter 9.

Lesson C8 in plain words

  • A test set is a list of cases with expected answers. Run, compare, count.
  • Success rate = passes ÷ total. assert turns a regression into an immediate failure.
  • Your QA experience maps directly onto evaluating agents.
