## 1. The loop, for this track

1. **Gather (fast pass).** Go through lessons 1 to 10 quickly: read the goals and the recap, run the commands, skim the rest. Use the **notes box** at the top of each lesson to dump what you learn and what confuses you.
2. **Refine.** Turn the notes into a map and cards (section 2 and section 3). Draw the map from memory first, then compare.
3. **Drill.** Work the flashcards (section 3), then the **Your turn** tasks and quizzes in each lesson.
4. **Round 2.** Run it again only on what is left (section 6): long scenarios, new tools, edge cases, odd details.

Open the whole toolkit any time from the **Study** button at the top: [Method](#study/method), [Drill](#study/drill), [Maps](#study/maps), [Notebook](#study/notebook).

## 2. The map: One research idea, from paper to practice

Each paper adds one capability to the agent loop. Map them onto it.

1. **Reason**: Chain of thought, self-consistency, tree of thoughts: think before answering. Lessons: [1](#aifield-1).
2. **Act**: ReAct and Toolformer: interleave thinking with tool calls. Lessons: [2](#aifield-2).
3. **Reflect**: Reflexion: learn from failed attempts. Lessons: [3](#aifield-3).
4. **Remember**: Generative agents and memory: store, retrieve, reflect. Lessons: [4](#aifield-4), [9](#aifield-9).
5. **Retrieve**: RAG surveys: chunking, retrieval, ranking. Lessons: [5](#aifield-5).
6. **Code**: Agentic coding practices and tool design (ACI). Lessons: [6](#aifield-6), [7](#aifield-7).
7. **Compare and plan**: Vendor guides compared; crews, browsers; a study map. Lessons: [8](#aifield-8), [9](#aifield-9), [10](#aifield-10).

## 4. Tips nobody tells you

- Read abstract, figure 1 and the results table first; decide if the rest is worth it.
- For every paper write: problem, idea, evidence, limits.
- Reproduce one idea in 30 lines of code.
- Compare papers by what they cost (tokens, time) not just accuracy.
- Keep a running list of terms in your glossary.

## 5. Read only these pages

When documentation links to eight more resources, you usually need one to three pages. For this track, start here (links are given from memory of stable documentation addresses; if one has moved, search the site for the title):
