Coding track · Lesson C9

Traces and a policy gate

By the end of this lesson you can:
  • record a trace of what an agent did, one JSON line per step
  • write a gate that allows, denies or defers each tool call
  • explain "deny by default"

The idea

Two production habits from Chapters 12 and 13, in a few lines:

  • A policy gate. The model proposes a tool call; your code decides whether it may run. Read-only tools are allowed. Risky ones need human approval. Anything unknown is denied. Deny by default means a tool nobody thought about is blocked, not allowed.
  • A trace. A record of every proposal and decision, so when something goes wrong you can reconstruct what happened. We store each step as a small dictionary and print it as one line of JSON. Files of such lines are called JSON lines and are easy to search and replay.

Sets, written with curly brackets and no labels ({"a", "b"}), are handy for "is this tool in the allowed group?" checks.

Line by line

  • READ_ONLY and NEEDS_APPROVAL are sets of tool names. They are the policy, kept in one visible place.
  • run_tool(name, human_ok=False) has a default for human_ok: if the caller does not say, it is False. A safe default.
  • The if / elif / else picks a verdict. The final else is the "deny by default" rule.
  • trace.append({...}) records the step number, the tool and the verdict. len(trace) + 1 numbers each entry.
  • The last two calls show the key behaviours. restart_service is denied without approval and allowed with it. delete_data is denied even with human_ok=True, because it is on no list at all. Some actions should never be available to an automated agent, whoever clicks approve.
  • The list comprehension [e["tool"] for e in trace if e["verdict"] == "deny"] is a short way to build a list: "the tool name of every entry whose verdict was deny".
Authorisation is policy

"The authorisation decision belongs to software policy, not model confidence." Notice that nothing in this code asks the model how sure it is. And because the gate sits in your loop, even a model that was tricked by prompt injection (Chapter 12) cannot call a tool the policy does not allow.

Lesson C9 in plain words

  • A gate checks every proposed tool call against policy. Unknown means deny.
  • A trace records each step as a line of JSON so you can reconstruct what happened.
  • The model proposes. Your code decides. Neither the gate nor the trace asks the model for permission.
