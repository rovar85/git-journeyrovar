What is a program?

A program is a text file of instructions that a computer follows from top to bottom, one line at a time, like a recipe. We use the language Python because it reads almost like English, it is the main language of AI work, and every agent example in this course is written in it. Python itself is a program called the interpreter: you hand it your text file and it carries out the instructions.

Three words you will hear constantly:

  • Code is the text you write.
  • Run means asking Python to follow the instructions.
  • Output is what the program prints back to you.

How the lessons work

Each lesson has the same rhythm, and you can stop after any step:

  1. The idea in plain words, tied to Enterprise Vault.
  2. The code player. A short program you can step through one line at a time. The highlighted line is the one that is about to run. Watch the Variables box (what the program remembers) and the Output box (what it has printed). This is the best way to see what code really does, and it works on a phone.
  3. Line by line. A plain-English explanation.
  4. Predict the output. A quiz that makes you think like the computer.
  5. Your turn. Small changes to try. Optional but powerful.

Everything shown by the player is a real run: I executed each program and recorded every step, so what you see is what Python really did.

Reading an error message

Errors are normal. Programmers see them all day. Python's error report is called a traceback, and it is easier than it looks. Read the last line first. It names the kind of mistake and says what went wrong. The lines above it show where. Here is an example, with the important parts marked:

Traceback (most recent call last):
  File "check.py", line 4, in <module>        <- WHERE: file check.py, line 4
    print(status)                              <- the line that failed
NameError: name 'status' is not defined       <- WHAT: you used a name that does not exist yet

Common ones you will meet, and what they usually mean:

ErrorUsually means
NameErrora typo, or you used a variable before creating it
SyntaxErrorthe code is not written in a form Python understands: a missing quote, bracket or colon
IndentationErrorthe spaces at the start of a line are inconsistent (Python uses spaces to group lines)
KeyErroryou asked a dictionary for a label it does not have
TypeErroryou mixed things that do not mix, like adding a number to text

Habits that make learning faster

  • Change one thing at a time, then run again. If it breaks, you know which change did it.
  • Predict before you run. Say what you expect the output to be, then compare. That is your QA instinct at work, and it is how understanding grows.
  • Run often. Little and often beats writing a lot and then debugging a lot.
  • Never put secrets in code. Passwords and API keys do not belong in a file you might share. Lesson C10 shows the safe way.
  • AI can help you code, and you stay the engineer. You may ask an AI assistant to explain a line or fix an error (paste the whole error message). But always read what it gives you, run it on harmless data first, and keep tools read-only until you trust them. Lesson C10 covers this properly.
