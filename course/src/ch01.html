Start with a game you already play

Finish this sentence: "The students opened their ___."

You probably thought of "books" or "laptops". You did not think of "volcano". Without any effort you ranked the possible next words by how likely they are.

That is the entire job of a language model. You give it some text. It gives back its best guess for what comes next, with a probability for each candidate. Everything else you have seen ChatGPT or Claude do is built on top of this one trick.

Teacher's note

Notice two things. First, the model never "decides what it wants to say". It only scores possible next words. Second, when it picks one, that word is added to the text and the whole thing is fed back in to get the next word. A long answer is just this loop repeated hundreds of times. Press "Let the model pick" a few times and you will see it.

Where does a language model sit?

People throw around many names. Here is how they nest, from the biggest idea to the smallest.

  • Artificial intelligence (AI) is the broad goal: software that does things we associate with intelligence.
  • Machine learning is one way to get there. Instead of writing rules by hand, you let the computer find patterns in data.
  • Deep learning is machine learning that uses neural networks with many layers.
  • A Transformer is a particular design of neural network that is very good at sequences like text.
  • A large language model (LLM) is a Transformer-style model trained at huge scale on text. GPT, Claude, Gemini and Llama are examples.
Teacher says

Do not just memorise the nesting. Ask what each box adds. Machine learning adds "learn from data". Neural networks add a flexible function that can be tuned. Transformers add a strong way to handle sequences. Large-scale training adds broad language ability.

Student asks

If ChatGPT is an LLM, is it "just the Transformer"?

No. The Transformer is the model design. A product like a chat assistant also has an interface, hidden system instructions, safety filters, often retrieval and tools, memory, and monitoring. The model is the engine. The product is the whole car. This matters later, because an agent is also "model plus a lot of software around it".

Words are really "tokens"

Strictly speaking, models do not read whole words. They read tokens, which are small pieces of text. A common word like "books" is usually one token. A rare or long word may be split into several pieces. Each piece is given an ID number, and the model works with the numbers. For now, when you read "word", think "token". Chapter 2 opens up the tokenizer and shows how the pieces are chosen.

What is a "model", physically?

This surprises almost everyone. A model such as Meta's Llama 2 70B, an open model whose details were published, is just two files on a computer:

  1. A parameters file. A very long list of numbers. These numbers are the "knowledge" of the model.
  2. A small program. It takes your text and those numbers and calculates the next-word probabilities. For this model, the program is only about 500 lines of code.

The "70B" means 70 billion parameters. Each one is stored in 2 bytes. So the size is easy to calculate yourself:

Why does predicting words make a model smart?

Imagine the model reads a Wikipedia article about a famous inventor and has to guess the next word at every position. To guess well, it needs to know when she was born, what she invented, and who she worked with. Nobody wrote these facts into the model. The model absorbed them because they help it predict. A simple-sounding goal forces the model to learn a lot about the world, and it stores that learning in its parameters.

You can think of the parameters as a blurry zip file of the internet. Unlike a real zip file, it is lossy: you get the gist of the text, not an exact copy.

Why it sometimes makes things up (hallucination)

Because the model is a blurry memory that fills in plausible words, it sometimes writes something that sounds right and is false. This is called a hallucination. A classic example is asking it for a book's ISBN number. The model knows an ISBN looks like a number of a certain length, so it produces a number of that shape. It may not exist.

Remember this

A language model produces the most plausible text, not the most true text. In engineering terms: a fluent answer is not a verified fact. When the answer matters, you show evidence, use a tool, retrieve documentation, or verify. Most of this course (retrieval, tools, evaluation, agents) exists to close the gap between plausible and true.

One more oddity. Researchers do not fully understand what each of the billions of numbers does. We know every mathematical operation the model performs, yet we cannot point at one number and say "this one stores the capital of France". The knowledge can even be lopsided. A famous example: a model can answer "Who is Tom Cruise's mother?" correctly but fail to answer "Who is that woman's son?". So we treat models as things we test by experiment: give inputs, look at outputs, and measure how often they are right. This is why evaluation gets its own chapters later.

Chapter 1 in plain words

  • A language model predicts the next token, over and over.
  • It is one box inside machine learning, deep learning and neural networks.
  • The model is a big file of numbers plus a small program. A product around it adds much more.
  • Learning to predict forces it to absorb knowledge, but only as a blurry memory, so it can state false things confidently.
