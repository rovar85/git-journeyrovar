Errors, validation and JSON

By the end of this lesson you can:
  • reject bad input on purpose, and catch the problem instead of crashing
  • turn a dictionary into JSON text, and back again
  • explain why "errors are data" in an agent

The idea

In Chapter 11 you saw a tool call fail because a model passed a value the API did not accept. Models make odd requests: a server that does not exist, a missing field, a typo. A good tool does not crash. It checks its input and returns a clear error that the model can read and adjust to.

  • raise ValueError("message") deliberately signals a problem.
  • try: ... except ValueError as problem: ... says "try this, and if that kind of problem happens, do this instead". The program carries on.

The second idea is JSON. Models and programs exchange text. json.dumps(result) turns a dictionary into JSON text. json.loads(text) turns that text back into a dictionary. That conversion is the bridge between your tool and the model: the tool's result becomes text that goes into the model's context.

Line by line

  • import json brings in a tool kit that Python ships with for reading and writing JSON.
  • In test_sql_connectivity, the first check rejects any server whose name does not start with "EV". It raises an error rather than guessing.
  • reachable = server != "EV03" pretends EV03's SQL link is down (!= means "is not equal to"). The result uses None if reachable else "timeout after 15s", a compact way to say "no error if reachable, otherwise this message".
  • The loop tries three names. try calls the tool. For WEB9 the tool raises ValueError, and except builds a result dictionary describing the problem. The error became data with the same shape as a normal result.
  • json.dumps(result) converts it to text. Notice Python's True, False and None become JSON's true, false and null.
  • Finally json.loads(text) proves the text can be read back into a dictionary.
Why this matters for agents

From Chapter 11: errors go back to the model as data so it can adjust, and arguments are validated before anything runs. It is also the structured-result rule from Chapter 10: put parsing and validation in code. And from Chapter 12: unknown or malformed requests should be refused, not guessed at.

Lesson C5 in plain words

  • Validate inputs and raise an error for bad ones. Catch errors with try / except.
  • Return errors as structured data so a model can react.
  • json.dumps makes text from a dictionary. json.loads reverses it.
